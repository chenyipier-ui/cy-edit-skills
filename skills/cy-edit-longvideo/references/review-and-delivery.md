# 成片复查

编译先产出待审工程，不能直接把 `ok` 当成剪辑完成。内部报告由实际保留的字幕与剪点生成；已删除的原句不会再次被算进重复清单。

1. 从 `成片文稿阅读索引.md` 逐份读完（每份约 8 分钟或 4000 字），再看 `成片复查.md` 的跨段疑点。不同表述也可能表达同一个意思；脚本的字词相似度只能提醒，低相似度不等于不重复。
2. 对疑似重复逐对判断：同一结论且没有新信息，留表达更完整、清楚、好听的一遍；新的条件、证据、递进、对比、纠正和必要回扣应保留。删除后再检查半句话、因果、时间、问答前提、指代和衔接。
3. 读实际试听音频的再转写差异与声音复测。多字、少字、密集口癖、短促声音只是候选；回听原音及剪后接缝，才判断尾音、咳嗽或吞字。不能用 ASR 差异直接扩大剪点。
4. 内容变化后更新计划，重编译；最终文稿、标题、章节、字幕一起重查。每次生成有新签名，旧复查不能套到新内容上。每次编译保留独立记录与工程依赖，不能覆盖上一版的素材。
5. 从内部 `review-decisions-template.json` 复制一份，填写实际判断，再运行 `RUN review --records "本轮内部记录目录" --input "review-decisions.json"`。

五项检查：意思是否重复、句子是否完整、逻辑是否连贯、指代是否清楚、标题是否有内容支撑。每个 D 编号需 `keep` 或 `revise` 和具体理由。删除后重编译，已消失的候选自然不再列出，不能对仍在成片的重复谎报“已删”。

`read_all: true` 只在实际通读后填写。`listening.status: done` 只在实际听过且有具体记录时填写；不具备声音能力就写 `not_done`，交付为待回听稿。最多两轮自动返修后仍拿不准的地方，按位置告诉用户，不把轮数用完当作通过。

再转写默认开启，按约 8 分钟分块，读取实际拼接后的 PCM。依赖缺失则自动准备；识别失败、离线无模型或明确跳过，报告未完成。重新转写不能代替正常速度完整听审和剪映内音画同步检查。

## 最终交付

交付目录仅一个 `.fcpxml`。长视频选多条时，同一个文件包含多个独立项目。内部 SRT、试听、复查和反馈 MD 留在工作目录，不作为用户交付附件。

打开方法：剪映首页“本地草稿”旁 `…` → “导入 PR 或 FCP 工程” → 选择该文件。多项目文件会出现草稿选择。若软件版本不提供该入口，先核对支持情况。FCPXML 是交换工程，不是 `.fcpbundle` 资源库，也不是导出的 MP4。

原视频、派生素材和进度条图片仍是工程依赖，不能删。单个 XML 不内嵌媒体；换电脑须让原片和依赖可访问，再重新关联。内部 SRT 仅供字幕兼容补救，工程已有字幕时不要重复导入。

给用户只说：剪好了什么、哪里需确认、怎么打开。例：“已剪成一条，字幕和标题已放好。开头 5 秒是封面标题参考。还有一处口误需要你听一下。用剪映的工程导入打开这个文件即可。”未听过、未在用户电脑导入过须说清，不报哈希或内部编号。

若帧对齐会截断保留词或带回已删声音，脚本会指出冲突。回听后换邻近静音、完整重录表达或保留更完整原句；不要反复微调时间硬过检查。
