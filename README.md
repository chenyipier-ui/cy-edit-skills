# CY 剪辑 Skills

**面向剪辑团队和工作室的内容精剪流程，把 AI 整理好的内容接到剪映里继续制作。**

这套流程由 CY 从团队实际剪辑经验中整理而来。你提供原始素材和内容目标，AI 助手完成内容梳理、删留判断、停顿处理和字幕整理，生成可导入剪映的 FCPXML 工程。剪辑师接着审片、修改、包装和导出，沿用团队熟悉的制作与商业交付方式。

**原始素材 → 内容精剪与复查 → 一个 FCPXML → 剪映审片、包装 → 客户交付**

当前版本：**2.3.0 · 公开测试版**。已完成合成组件检查，并有 macOS 剪映专业版 11.7.0 的导入、文字修改和保存重开记录；真人素材完整内容与听感验收、Windows 实机验证仍待补齐。[验证范围](docs/VALIDATION.md)

## 两个 Skill，按内容选择

| Skill | 适合的素材与目标 | 主要处理方式 |
| --- | --- | --- |
| [单主题口播精剪](skills/cy-edit-shortvideo/) `cy-edit-shortvideo` | 同一个人围绕一个具体主题录制的一条或多条素材 | 清理重录、同义重复、密集口癖和多余停顿；默认保留原话、原速和原顺序，精剪成一条 |
| [长内容整理与剪辑](skills/cy-edit-longvideo/) `cy-edit-longvideo` | 直播回放、访谈、对话、课程等多话题长内容 | 通读后梳理主线，整理成一条完整精简内容，或拆成多个各自讲完整的话题；必要的结构取舍沿用或取得用户授权 |

选择依据是内容结构。单主题长口播可以用口播精剪；需要跨话题重组、处理访谈或拆条时用长内容版。

## 围绕实际剪辑习惯设计

- **把后续编辑留在剪映。** 交付目录只放一个 FCPXML。多条结果保留为文件内的独立项目，字幕与标题可编辑，便于继续加工和客户返修。
- **先理内容，再处理剪口。** 结合全文判断重复、递进、条件和举例，保住原意、因果、指代、问答前提及说话人归属。词级时间辅助定位，疑似咳嗽、漏字和尾音需要回听确认。
- **剪完再读、再听。** 对实际剪后音频重新识别，按成片顺序检查全文、同义重复和逻辑，再回听疑点。修改后重新复查；未完成听审的版本会保留待审状态。
- **把反馈变成可管理的经验。** 当前项目意见与长期偏好分别记录。两套 Skill 共用经验库，长期偏好可以更新、撤销，并记录本项目实际采用了什么。
- **适合团队接着完成交付。** 保留原素材，分析、试听、复查和反馈记录放在内部工作目录。团队可在剪映中继续使用自己的模板与视觉风格。

默认提供白字阴影字幕、顶部内容标题、前 5 秒的中央封面标题参考；超过两分钟的内容增加底部进度条及章节，横竖版分别布局。**专注内容精剪，不添加配乐、音效、转场、调色或花式包装。**

工程导出本身并非独有能力。这套 Skill 的重点，是把内容取舍、声音复查、反馈经验与剪映后续制作串成一套工作流程；目前没有同素材横向测试，不承诺比其他工具更快或剪得更好。

## 安装

需要能够读取本地素材、运行脚本并支持 Skills 的 AI 助手。使用 [Skills CLI](https://github.com/vercel-labs/skills) 时，在项目目录运行：

```bash
npx skills add chenyipier-ui/cy-edit-skills
```

GitHub 访问不便时，可以从 Gitee 官方镜像安装：

```bash
npx skills add https://gitee.com/chenyipier/cy-edit-skills.git
```

按提示选择一个或两个 Skill，以及要使用的 Agent。默认安装到当前项目；跨项目使用可加 `-g`。Skills CLI 当前要求 Node.js 22.20 或更高版本。

也可以从 [GitHub 发布页](https://github.com/chenyipier-ui/cy-edit-skills/releases/tag/v2.3.0) 或 [Gitee 国内下载页](https://gitee.com/chenyipier/cy-edit-skills/releases/tag/v2.3.0) 下载单独安装包，解压后放入 Agent 的 skills 目录。两边的 v2.3.0 ZIP 内容和 SHA-256 一致，Gitee 附件直接从其文件服务下载。每个 Skill 都附有许可、版本和使用说明。[完整安装说明](docs/INSTALL.md)

首次处理素材可能下载 Python、媒体依赖及语音识别模型；代码安装与运行环境准备是两个步骤。启动入口面向 macOS 和 Windows，Windows 尚未完成实机验证。仓库或 ZIP 不包含模型、运行环境、客户素材及用户经验库。

GitHub 作为维护来源，每次发布新 Release（包括公开测试版）后，自动同步代码、标签、版本说明和安装包到 Gitee，并回读核对文件校验值。同步进度见 [镜像工作流](https://github.com/chenyipier-ui/cy-edit-skills/actions/workflows/mirror-gitee.yml)，维护步骤见 [发布说明](docs/PUBLISHING.md)。国内镜像不改变依赖及模型的下载地址。

## 怎么开始

安装后，把素材位置和目标直接告诉 AI 助手，例如：

> 用 cy-edit-shortvideo，把这个文件夹里围绕同一主题录的口播精剪成一条，保留原话和自然气口，工程用于导入剪映。

> 用 cy-edit-longvideo，读完这场访谈，整理一条完整精简版，再建议哪些话题值得独立切片。先说明取舍，沿用我确认的方向继续做。

Agent 负责执行脚本并按已有要求推进。遇到无法核实的事实、素材缺口或尚未授权的结构取舍时，再就具体问题沟通。处理时间取决于素材长度、电脑性能和下载缓存。

## 导入与返修

FCPXML 是工程交换文件，需要在剪映中导入。它引用原素材和部分生成的图片资源，**没有把素材打包进文件**；请保留项目工作目录和原素材。跨电脑交接时一并转交依赖并核对重链接结果。

导入后检查画面、声音、字幕、切点和标题布局，再完成包装与导出。实际兼容性与剪映版本有关，当前验证记录见 [兼容说明](docs/COMPATIBILITY.md)。Skill 重新生成的工程与剪辑师已手工加工的草稿分别维护，避免覆盖人工修改。

反馈可以直接说“第三段删掉，这条片子停顿再紧一点”，也可以说“以后我的片子都保留自然气口”。前者用于本项目，后者可记录为长期偏好；新的明确要求优先。
