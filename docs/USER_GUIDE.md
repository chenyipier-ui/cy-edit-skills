# cy-edit 口播剪辑 Skill 使用说明

2026 年 11 月 12 日 · CY · 版本 2.5.0。面向剪辑团队、工作室与内容创作者。

这两套 Skill 把团队的内容精剪经验交给 AI Agent 执行。你提供素材和目标，它通读全文、判断删留、完成剪辑并复查，交付可导入剪映继续修改的 FCPXML 工程，也可在支持该格式的 Final Cut Pro 中导入后精修。原画面与声音在本机处理；内容判断由你使用的 Agent 完成。配乐、音效、转场、调色和成品导出沿用团队自己的流程。

## 一、分工：按内容与目标选择

| | 单主题口播精剪 | 长内容整理与剪辑 |
| --- | --- | --- |
| 名称 | `cy-edit-shortvideo` | `cy-edit-longvideo` |
| 素材 | 同一人围绕一个主题录的一条或多条口播 | 直播、访谈、对话、课程或多个相关长素材 |
| 目标 | 一个主题剪成一条，讲得更清楚、更紧凑 | 完整内容精简、主线重组，或拆成几个完整话题 |
| 主要动作 | 删重录、同义重复、密集口癖和多余停顿 | 读完全文，梳理主题、组织结构，再完成精剪 |
| 顺序 | 默认原顺序、原话、原速 | 按确认的结构重组，保留因果、条件、时序和说话人归属 |
| 是否需要确认 | 普通清理按已有要求直接做 | 新的结构或拆条方案先确认；已有明确授权直接沿用 |
| 访谈与多人 | 面向同一人的单主题口播 | 区分提问与回答、说话人归属，保留问答前提 |
| 交付 | 默认一个 FCPXML、一个项目 | 一个 FCPXML，多条内容是多个独立项目 |
| 反馈 | 每轮保存 MD，长期偏好可用于下次 | 两套 Skill 共用同一份经验库 |
| 不应误解为 | 只适合短时长素材 | 只要文件大或时长长就必须使用 |

**一个主题剪一条，用 shortvideo；需要重组或拆成几条，用 longvideo。** 几分钟到二三十分钟的单主题口播常用前者，一小时访谈或直播常用后者；长度是参考，内容结构才是判断依据。

## 二、使用条件

| 条件 | 适合 | 不适合直接交给这套流程 |
| --- | --- | --- |
| 素材 | 本地可读取的口播、访谈、直播回放、课程；语音是主要内容；可附原片 SRT | 画面主导的 Vlog、音乐片、多机位同步或大量空镜包装；没有可读取的素材 |
| 声音 | 人声可辨，有足够上下文；原片与字幕对应 | 严重失真、多人持续重叠、配乐压过人声，无法判断原意 |
| 语言 | 默认中文；英文等其他语言在任务中明确告知 Agent | 把语言混杂、专名密集的素材当作无需人工校对的逐字稿 |
| 电脑 | macOS Apple Silicon / Intel，Windows 10/11 x64；有可用磁盘和首次下载网络 | 手机端；首次运行时既没网络也没缓存；Linux、旧系统或 Windows ARM 不在默认安装入口适配范围 |
| AI 助手 | 支持 Skills，能读取本地文件、执行脚本并检查声音的 Agent | 只能聊天、无法访问本地素材或运行命令的网页对话框 |
| 剪辑软件 | 能导入 FCPXML 工程的剪映专业版，或支持该格式的 Final Cut Pro | 手机剪映 App，或没有工程导入能力的客户端 |
| 交付目标 | 团队接着修改、包装、审片并输出客户成片 | 希望一步得到带音乐、转场和包装的最终 MP4 |

语音识别在本地运行；Agent 如何处理文稿取决于其服务和配置。Skill 可免费使用，Agent、模型服务或剪辑软件自身的费用按各自规则。

## 三、安装两步

**第一步：安装 Skill。** 已有能执行安装的 Agent，可以直接说：

> 请从官方仓库 https://gitee.com/chenyipier/cy-edit-skills.git 安装 cy-edit-shortvideo 和 cy-edit-longvideo，安装到我正在使用的 Agent，并确认可以读取 SKILL.md。

也可以在项目目录使用 Skills CLI：

```bash
npx skills add chenyipier-ui/cy-edit-skills
# 国内来源
npx skills add https://gitee.com/chenyipier/cy-edit-skills.git
```

两条命令选一条即可。按提示选择 Skill 和 Agent；跨项目可用加 `-g`。CLI 需要 Node.js 22.20 或更高版本。无需 CLI 时，从 [GitHub 下载页](https://github.com/chenyipier-ui/cy-edit-skills/releases/tag/v2.5.0) 或 [Gitee 下载页](https://gitee.com/chenyipier/cy-edit-skills/releases/tag/v2.5.0) 下载单独包或合集，让 Agent 放入正确的 skills 目录。

**第二步：让 Agent 准备环境。** 新开会话，让它读取对应 Skill 并处理一条素材。入口会在用户目录自动准备独立 Python、媒体工具和语音识别模型，后续复用缓存。首次下载时间取决于网络与模型；后续无需重复安装。识别和整理的速度随素材、模型与电脑变化；返修会复用音频未变且模型、语言一致的识别结果。

安装完成后日常与 Agent 对话即可，无需反复操作终端。完整命令、ZIP 结构与自动更新机制见 [安装说明](INSTALL.md)。

## 四、直接这样说

**单主题口播：**

> 用 cy-edit-shortvideo，把 ~/Movies/口播素材 里的同主题口播剪成一条，竖版发抖音。保留原话、原顺序和自然气口，删掉重录、无信息增量的重复、密集口癖和多余停顿。交付可导入剪映的 FCPXML。

**长访谈做完整精简版：**

> 用 cy-edit-longvideo，读完「访谈文件路径」，围绕「本期目标」整理一条完整精简版。保留关键例子和问答前提，先给我看主线与主要取舍。

**直播拆话题：**

> 用 cy-edit-longvideo，把「90 分钟访谈文件路径」整理成 3 条能单独发的短视频，说明各条的观点和预计时长。不要为了凑数量强行切片，按我确认的方案完成剪辑。

**完整精简版和切片都要：**

> 同时整理一条完整精简版和几条独立话题，分别组织内容，放进同一个 FCPXML 的独立项目里。

非中文素材补一句语言，例如“这是英文口播，剪成横版发 YouTube”。有时长、受众或必须保留的信息也可以一并说明；无需先填写一整套问卷。

## 五、Agent 会做六步

1. **读取目标与素材。** 登记文件、检查声音和画面信息，读取适用的历史偏好。
2. **转写并读完全文。** 按顺序理解所有素材，识别主题、重复、递进、例子和关键信息。
3. **决定删留与结构。** 普通口播按已有要求清理；长内容给出主线和拆条建议，涉及新的结构取舍时取得确认。
4. **生成工程。** 落实剪点、停顿、字幕、内容标题、封面参考和章节。
5. **剪后复查。** 对实际剪后音频重新转写，通读最终文稿、检查重复与逻辑，回听可疑声音；修改后重新检查。
6. **交付与返修。** 给出一个 FCPXML 和导入方法，记录本轮意见，继续修改新版本。

已确认的方向直接沿用。遇到素材缺失、事实矛盾或会改变原意的取舍，Agent 会就具体问题与你沟通。

## 六、交付内容与版式

**交付目录只有一个 FCPXML 工程文件。** 单条内容是一个项目，多条内容是同一文件中的多个独立项目。分析、试听、转写和反馈保存在项目工作目录，供返修复用。

| 元素 | 竖版 | 横版 |
| --- | --- | --- |
| 原画面与原声 | 保留，按画幅组织 | 保留，按画幅组织 |
| 字幕 | 白字阴影、单行、位于画面下部；9:16 默认约 13 个汉字 | 白字阴影、单行、位于画面下部；16:9 默认约 24 个汉字 |
| 常驻内容标题 | 顶部居中，两行 | 宽横屏左上，两行；接近方形时顶部居中 |
| 封面标题参考 | 前 5 秒居中，可编辑、可删除 | 前 5 秒中下部，可编辑、可删除，减少遮挡中央人脸 |
| 进度条与章节 | 超过两分钟时出现在底部 | 超过两分钟时出现在底部，横屏单独适配 |
| 文字与画幅 | 文字可编辑，适配画布尺寸 | 文字可编辑，支持方形、4:3、16:9 和 4K 等布局 |

字幕默认去普通句读，保留小数等有意义的符号；英文按显示宽度计算，实际换行服从可靠词句边界。3:4、1:1 和 4K 等画幅自动换算，封面参考可在确定封面后删除。

这是基础可编辑版式。**不做配乐、音效、转场、调色、花式包装，也不把最终 MP4 导出作为 Skill 的交付。** AI 做好内容精剪后，团队在剪映或 Final Cut Pro 里完成自己的视觉风格和成品。

FCPXML 引用原素材和工作目录中的资源，文件本身不包含媒体。原片与工作目录都要保留；跨电脑移交时一起转交，按实际位置重链接。

## 七、导入剪辑软件与提意见

- **剪映专业版**：在首页“本地草稿”右侧“…”中选择“导入 PR 或 FCP 工程”，选择 FCPXML；客户端界面变化时使用对应的工程导入入口。
- **Final Cut Pro（Mac）**：选择“文件 → 导入 → XML”，选择 FCPXML。[Apple 导入说明](https://support.apple.com/zh-cn/guide/final-cut-pro/verdbd66ae/mac)

多项目时分别选择需要的内容。检查素材链接后，继续改字幕、调整标题、加包装并导出。不要把 FCPXML 当作普通视频导入媒体素材箱。[工程说明](COMPATIBILITY.md)

导出成品前完整审看画面与声音。原片不要随意移动或改名；混合帧率素材出现同步问题时，让 Agent 定位具体文件并处理后重新生成工程。

返修时直接指出位置和目标：

> 第三段删掉，开头保留；这条片的停顿再紧一点，重新出一个工程版本。

> 第 40 秒前后衔接不顺，请回听并修一下，不要改原话。

长期偏好要明确说“以后”：

> 以后我的口播都保留自然气口，不要把思考停顿全部剪没。这条作为长期偏好保存。

本片修改与长期偏好分别保存，长期偏好可以更改或撤销。转写、审阅包、复查与反馈记录保存在项目工作目录，方便追溯；遇到报错，把原话和对应任务说明交给维护人。Skill 重新生成的版本与剪辑师已包装的草稿分开保留，方便比较和回退。

## 八、和同类工具的分工

下表依据各家公开页面整理，查阅日期为 **2026-11-12**。功能、导出格式和套餐以官方当前版本为准；表格用于选工作方式，不作速度或质量排名。

| 工具 | 官方公开的主要方式 | 与 cy-edit 的分工 |
| --- | --- | --- |
| [剪映「智能剪口播」](https://www.jianying.com/) | 在剪映内识别无效词，按文本剪口播 | 已在剪映里、想直接清理素材时方便；cy-edit 把全文阅读、结构取舍和复查组织成 Agent 流程，再交回剪映 |
| [Descript](https://www.descript.com/features) / [Underlord](https://www.descript.com/underlord) | 文本驱动编辑、去填充词、AI 协作编辑与生成片段 | 适合在其编辑环境内完成制作；cy-edit 面向本地素材和剪映后续工作流 |
| [Gling](https://www.gling.ai/) / [工程导出说明](https://www.gling.ai/help) | 清理重录、静音、填充词，文本剪辑，AI 短片及 XML 时间线导出 | 适合快速清理创作者素材并接其他编辑器；cy-edit 将全文判断、返修经验和剪映工程衔接放在一起 |
| [OpusClip](https://www.opus.pro/) | 将素材切成社交片段，配合字幕、重构图和发布工具 | 适合快速生产社交切片；cy-edit 更适合围绕明确内容目标保留完整论述、整理长版或独立话题 |
| [AutoCut（mli/autocut）](https://github.com/mli/autocut) | 自动生成字幕，在文本中选择保留句子，再裁切并保存对应视频片段 | 适合用文本手动决定删留；cy-edit 把内容判断交给 Agent，并交付可继续修改的工程 |
| [auto-editor](https://auto-editor.com/) | 按声音响度、运动、字幕等分析方法自动剪辑，可使用命令行 | 适合可配置、批量执行的剪辑规则；cy-edit 由 Agent 结合全文语义决定内容取舍 |

其他工具也有 AI 理解、文本编辑或工程导出能力。**cy-edit 的重点是把实战团队经验、全文内容判断、剪后复查、反馈复用和剪映后续制作连成完整流程。**

代价也明确：需要 AI Agent；阅读全文、重组和复查比单次规则清理多出处理步骤，耗时随素材和模型变化；包装及成品导出由团队完成。它适合重视内容和返修效率、用剪映交付的团队与工作室。
