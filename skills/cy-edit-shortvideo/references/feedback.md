# 每轮反馈自动保存与跨项目经验

用户只需正常说意见。Agent 先保存，再修改。无须聊天平台消息 ID，也不让用户准备 JSON。两套 Skill 使用同一套事件、MD 回执和采用记录。

## 保存位置

- 本项目 `feedback/反馈记录.md`：逐条原话、这次怎样改、适用条件、验证状态。
- 本项目 `feedback/turn-receipts/`：本轮预计条数、成功条数、缺项、文件校验结果。
- 本项目 `experience/本项目经验采用清单.md`：每条经验采用、跳过或待判断，以及具体影响哪个动作。
- 个人共享库：Mac `~/.cy-edit/shared/experience/经验库.md`；Windows `%APPDATA%\cy-edit\shared\experience\经验库.md`。`CY_EDIT_EXPERIENCE_DIR` 可指定另一数据根目录。运行环境分开，经验格式共享。

JSON 事件是可恢复真源，MD 是给人看的视图。改规则用命令，不手改生成的 MD。用户素材、反馈、个人经验不放入可分发安装包。

## 每轮一条命令

`RUN feedback --project "项目目录" --input "本轮反馈.json"`

短视频的项目目录使用 prepare 的 workdir；长视频使用 prepare 的 project。同一项目持续沿用。输入由 Agent 写：

```json
{
  "message": "这句重复的删掉。以后字幕都用白字阴影。",
  "items": [
    {"text":"这句重复的删掉", "scope":"project", "action":"下一版删除该句并复查衔接", "lesson":"本片重复句只保留一遍"},
    {"text":"以后字幕都用白字阴影", "scope":"user", "authorization":"以后字幕都用白字阴影", "preference_key":"subtitle.style", "lesson":"字幕使用白字阴影", "applies_when":"该用户的口播与长内容剪辑"}
  ]
}
```

一条消息里的每项意见都登记。仅“这次”用 `project`；用户明确“以后都这样”才用 `user` 并保存授权原话。可能通用但未经验证的思考用 `candidate`；不能一收到反馈就升级成所有用户的硬规定。

先写事件，再生成项目 MD、共享 MD 和回执；最后读回校验。只有 `feedback_saved: true` 才说“本轮意见已保存”。发生部分失败时，保留输入重跑同一份，按进度恢复；脚本在输入里自动保存一个本地回执号；原输入或其副本换文件名重试也不会重复写入。新一轮使用新的输入文件，不带旧回执号，即使原话相同也会单独记录。无需 Agent 或用户编造消息编号。不能只看到一个 MD 存在就说本轮全部成功。

## 更新、撤销与恢复

- 修改长期偏好：`operation: "update"`，`target_ids: ["旧经验真实编号"]`，同一 `preference_key`，写新规则与用户授权原话。
- 撤销：`operation: "revoke"`，`target_ids` 指向生效条目；保留历史，停止后续采用，不删除用户原话。
- 恢复已撤销规则：记录一条新的、有新授权的规则。撤销替代项不会自动复活更早版本。
- 同一偏好键有冲突时先待判断，当前用户要求优先；不是简单取时间最新的一句。

## 后续项目怎样用

prepare 自动读取共享经验。Agent 检查适用条件；只在当前项目合适时采用。读取成功不等于已经应用。把实际选择写成一份文件：

```json
{"decisions":[{"experience_id":"从 experience 返回值复制真实 ID","decision":"adopt","reason":"本项目同属该用户口播","application":"沿用白字阴影，不改变剪辑取舍"}]}
```

运行 `RUN experience --project "项目目录" --decisions-file "经验选择.json"`，脚本更新采用清单。没提供的新增项保持 `pending`；明确不适用写 `skip`，都要理由。用户反馈以后、恢复中断以后、下一版编译之前刷新一次。编译入口也会自动刷新，并在本次编译记录里保存经验采用快照；新增待判断项不会自动宣称已应用。撤销和替代会剔除旧经验，已经导出的旧工程保留原样，新版重新生成。

旧长视频 JSON 经验会合并到共享库；同 ID 不同内容会停止覆盖。旧短视频 `经验库/*.md` 保留，experience 返回旧文件路径，Agent 读取后按原始证据逐项迁入，不能静默丢失，也不能把过期 MD 直接当生效规则。

用户看到的回话保持简单：“两条意见已保存。一条只改这次，一条记为以后偏好。正在修改下一版。”已保存、已应用、已验证分别记录。
