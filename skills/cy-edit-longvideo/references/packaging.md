# 字幕、标题与底部进度条

全部文字使用可编辑的 FCPXML 原生标题。进度条只有两张纯色图片，不含字；文字不烧进图片或视频。两套 Skill 使用同一份 cy_packaging.py。

| 元素 | 竖版（9:16） | 横版（16:9） | 时序与写法 |
| --- | --- | --- | --- |
| 字幕 | 中心在画面约 72% 高处 | 约 85% 高处，字高约为画面高的 4.8% | 白字、黑阴影、单行；按真实词边界拆分 |
| 内容标题 | 顶部居中，约 17% 高处 | **左上角**，左边距 4.5% 画宽、上边距 5.5% 画高 | 两行，整条常驻；直说主题和结论，不卖关子 |
| 封面标题参考 | 画面中央 | 中线略偏下（避开上三分之一的人脸），小标签在其下方 | 两行，只显示前 5 秒；标“封面标题参考” |
| 进度条 | 贴画面最底部，1080×1920 时高 44px | 1920×1080 时高 40px，章节字约 24px | 超过 2 分钟才加；从首个章节起点出现并连续填满 |

字号换算（剪映 11.7 实测）：屏幕上一个汉字宽 ≈ `fontSize × 画布高 / 1080`。同一个 fontSize 在竖版上比横版大 1.78 倍，所以版式模块按“占画面短边的比例”设计、再换算回 fontSize，3:4、1:1、4:3、4K 都自动适配，不要手改单个数字。接近方形（宽高比小于 1.5）的横向画面把内容标题改为顶部居中。字数上限也按画宽自动算：16:9 字幕 24 字、标题每行 16 字、封面每行 14 字。

字幕默认竖版（9:16）最多 13 字、横版（16:9）24 字，其他画幅按画宽自动算。词本身超长或只有整句时间时保留可靠时间，不平均分配逐字剪点；报告超长字幕以便核对。去句读，但保留 3.5、1,000、3:1 等有意义的数字符号。转写纠错只改错字，不改说话者实际意思。

内容标题：优先“话题 + 结论”，竖版每行建议 12 字以内，横版 16 字以内（左上角标题不宜超过画宽四成）。给两个备选，默认采用第一个；除非涉及事实或用户明确要求选择，不再发一轮问卷。

封面标题参考：给三个备选，默认采用第一个。用真实反差、问题或有来源的数字留下阅读兴趣，不能夸大；片子必须兑现。与内容标题不能是同一句。示例里的数字和身份不迁移到真实用户。

章节名根据最终文稿写，通常 2–5 个字。数量随内容变化，不为了凑 3–5 个而拆坏逻辑。用 `｜` 连成一行，过长就缩短。`start` 指向最终保留的剪辑段或原文编号。若有开头钩子，首章节从钩子之后开始；没有独立钩子可从开头开始。填充从章节起点 0% 到片尾 100%，采用图片位移动画，不依赖未确认的横向缩放动画。

```json
{
  "content_title": ["先理清内容主线", "再删除重复表达"],
  "cover_title": ["剪短一点", "就一定讲清了吗"],
  "chapters": [{"title": "理主线", "start": "s001"}, {"title": "去重复", "start": "s002"}]
}
```

短视频把这些字段写在计划顶层；长视频写在每个候选内。短于两分钟可用 `chapters: []`。先通读拟保留全文，拟标题并编译；最终复查若改变内容，标题与章节也要重写，不能沿用旧文案。

## 导入证据的边界

本地 macOS 剪映 11.7 的本次合成验收观察到：原生文字位置、换行、白字阴影、内容标题底色、前段封面、底部位移填充可显示；字幕实际改字后重开仍保留。一个 FCPXML 内两个项目可被识别并分别保存。此结论只覆盖本次写法与环境，不承诺所有字体、剪映版本、Windows 导入器或 FCP 原生样式完全保真。

横竖版布局都是参考版式；长标题、脸部位置与平台遮挡需按实际画面调整，不自动裁脸。其他包装、音乐、音效、转场仍不加入。

[Apple 文字样式说明](https://developer.apple.com/documentation/professional-video-applications/text-style) 与 [位置变换说明](https://developer.apple.com/documentation/professional-video-applications/adjust-transform) 解释 XML 字段；其他软件能保留多少，以导入观察为准。
