# 将长内容拆为多个独立话题

读完全部内容后按话题拆条，不按源文件、时间、采访问题或转写块直接分。寻找对观众有价值且能独立讲完整的内容：问题与判断、案例与方法、人物选择及其证据都可能成为话题。这些是发现线索，不是要求用户选择的新分类。

## 每条五项判断

1. 对目标观众有具体观看价值。
2. 一句话说得清核心问题或观点。
3. 有原因、解释、过程、案例或细节支撑。
4. 不看其他条也能理解，背景、指代和问答成立。
5. 可由真实原话自然重组，条件和原意不变。

观看价值按本项目目的判断，不套用某个客户的目标。

## 从索引到推荐

- 汇总分散在全片的观点、原因、案例、条件与收尾。
- 候选标 ready、needs_material 或 not_recommended。仅一句金句没有论据，应说明缺什么；没有合格切片可以不推荐硬剪。
- 按叙事功能分配材料：同词不等于同作用，同经历可包含不同信息点。
- 每条有开头、必要背景、主张、证据／过程、结尾；顺序可调整。
- 给逐条可读方案和来源附录，再整批检查主题边界、复用与开头结尾分配。
- 按观看价值和完整性给推荐顺序。用户决定采用哪些，不把首次展示数量写成技术上限。

结论、原因和案例通常在同一条完成，不能为了凑数拆成几条残缺内容。用户选择连续系列时说明依赖关系，不把它标成独立切片。

## 给用户的方案

每条用标题、主线、删留理由把选择讲清楚。受众与目的沿用项目要求，原文位置和预计时长由脚本带出；必要背景、证据和结尾融进稿件，不要求额外填一张复杂执行卡。

动作采用前置／保留／压缩／合并／删除／后置，写清来源位置、新位置和理由。别只写“节奏紧凑”。缺口标需补问、需补录、需补素材或待确认，不能替人物补台词。

整批另有信息点归属表：来源、主归属、作用、其他条是否复用及理由。身份可简短复用，完整论据不因换标题就变新内容。已发布内容只有拿到资料才核对，缺资料写未核对。

一个计划可包含多条输出，每条保留独立项目，一起写入一个 FCPXML。用户明确需要完整精简版和话题切片都交付时，用 both 记录两种输出的组合；共用分析与来源资料，分别设计结构，不新增第三套处理方法或重复转写。
