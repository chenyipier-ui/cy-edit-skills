## 可复现的发布检查

2026-11-12 在 macOS、Python 3.12.13、PyAV 16.0.1 的发布隔离目录重新执行：下述合成检查通过，3 个生成的 FCPXML 均通过本地 FCPXML 1.10 DTD 校验。Skills CLI 1.8.1 从本地发布目录向隔离项目安装两个 Skill 成功；这项记录仅证明本地包可被发现和安装。远端发布安装及 CI 的最终结果见对应 Release 和 Actions。

首轮 Windows PowerShell 5.1 语法检查发现口播入口的中文字符串存在编码解析错误，发布整理为该脚本添加 UTF-8 BOM，并将 Windows 脚本与 ZIP 内换行统一为 CRLF。该修复针对入口解析，不代表 Windows 完整安装与剪辑已经实测。

发布后已分别从 GitHub 与 Gitee 的公开来源向隔离 Codex 项目安装两套 Skill，85 个文件一致（Windows 换行规范化后比较）。两边 v2.3.0 的三个 ZIP 及 SHA256SUMS 均经未登录公开下载逐字节核对；Gitee 下载落在其 `foruda.gitee.com` 文件服务。镜像安装检查没有使用国内各运营商、多地区或受限网络的独立测试环境。

`tests/run_checks.py` 在独立目录生成短合成视频，检查：

- Python、JSON、Mac 入口语法，文档本地链接和 Skill 元信息。
- 两套 CLI 能读取帮助，单独安装包包含一致的许可和版本。
- 口播最小删留计划可编译为一个 FCPXML。
- 长内容双候选计划生成一个包含两个独立项目的 FCPXML。
- 多字 token 不伪造逐字时间，词内切点和伸入已删邻句的帧边界会被拒绝。
- 未说明理由的重复疑点无法闭环；内容修改使旧复查结论失效。
- 反馈更新、撤销、重试去重和新一轮相同反馈分别记录；两套共享模块一致。
- 指定本地 Apple FCPXML 1.10 DTD 时，检查生成工程的 DTD 合法性。

执行方式：先具备 Python 3.12、PyAV 16.0.1、FFmpeg，再在仓库目录运行：

```bash
python tests/run_checks.py --output /path/outside/repository/checks
```

输出目录必须为空且位于仓库外。结果及日志保留在指定目录。测试采用隔离经验库，显式跳过模型再识别，也不打开剪映。CI 同样检查合成流程；Windows 作业仅解析 PowerShell 语法。CI 通过不能替代真实使用验收。
